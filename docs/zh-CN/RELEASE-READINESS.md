项目与锁文件版本已统一为 `0.1.0-alpha`。仓库根目录包含 Apache-2.0 LICENSE，独立图标声明继续保留。正常工作区和案例恢复共用只读的 12 表内容校验器，案例在备份前保存非空个人时间偏好。

干净安装发现开发依赖公告 GHSA-68fv-2mgg-jv7q，已定向将锁文件中的 source-map-js 从 1.2.1 更新至 1.2.2。随后第二次干净 npm ci、类型检查、构建、全部 55 项测试、完整审计及案例／恢复均通过。此前 Fastify 与间接依赖补丁仍包含在候选中。

私有原始日志和源码清单保存在被忽略的 `artifacts/release-alpha/`。排序后的逐文件源码清单 SHA-256 为 `3d2ea6519528d9e73c275fdf205bfeb7d5130a2d6d333c17eb09ea1ff3777bc9`，为避免自引用，排除本报告的两种语言文件及配套截图。交接前将候选副本与最终源码逐文件比较。文档附件不包含数据库备份或会话凭据。

独立 Chrome 在当前环境的沙箱下启动失败，因此 UI 使用受支持的内置浏览器验证。两次浏览器工具确认超时，读取当前状态并重试明确的本地操作后继续完成验证；工具超时没有被记作应用测试通过或应用失败。

## 发布交接与限制

计划以 `v0.1.0-alpha` 标签分发源码树，并标记为预发布。见[版本说明](RELEASE-NOTES.md)和[发布检查](RELEASE-CHECK.md)。之后有相关改动时需重跑受影响检查，最终标签必须指向同一已验证源码树。

本次是当前主机上干净源码目录的安装，复用了既有 PostgreSQL 容器，不是全新机器或公网托管验证。没有重跑负载、真实团队试用或正常工作区实际备份演练。模拟恢复不能替代升级已有工作区前对实际备份的检查。公网 HTTPS、远程团队访问和外部集成仍在本 alpha 范围之外。
