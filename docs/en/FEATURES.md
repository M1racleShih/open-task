# Features and controls

[简体中文](../zh-CN/FEATURES.md)

Find an explanation by the action you want to perform. Start with [your first task](FIRST-TASK.md), then use the [advanced case](CASE-CSV-EXPORT.md) for multi-person workflows.

## Create and deliver

| Feature | How to use it | Read |
| --- | --- | --- |
| Private drafts and temporary tasks | Save and edit your own drafts. Use Temporary tasks before assigning a project; drafts may omit dates. | [Read](USER-GUIDE.md#task-workflow-from-creation-to-review) |
| Delete drafts | Creators can delete their unsubmitted drafts. Closing a form does not delete the task. | [Read](USER-GUIDE.md#task-workflow-from-creation-to-review) |
| Creation approval and return | Submit proposed work for the appropriate approvers; edit and resubmit returned tasks. | [Read](USER-GUIDE.md#task-workflow-from-creation-to-review) |
| Direct issue and reviewer defaults | Leaders can issue their own drafts directly. Reviewer defaults follow role and project rules; valid reviewers can also be selected explicitly. | [Read](USER-GUIDE.md#task-workflow-from-creation-to-review) |
| Accept and start work | Owners can accept then start, or use Accept and start together. | [Read](USER-GUIDE.md#task-workflow-from-creation-to-review) |
| Unable to accept and reassignment | Owners explain why they cannot accept; the issuer responds, and a replacement owner accepts again. | [Read](USER-GUIDE.md#task-workflow-from-creation-to-review) |
| Result submission and review | Owners submit results, reviewers accept or return them, and improved results can be resubmitted. Earlier submissions and reasons remain. | [Read](USER-GUIDE.md#task-workflow-from-creation-to-review) |
| Rename, cancel and follow-up tasks | Leaders can rename or cancel unfinished tasks. Ended tasks cannot reopen; create related follow-up work. | [Read](USER-GUIDE.md#task-workflow-from-creation-to-review) |

## Progress, checklists and help

| Feature | How to use it | Read |
| --- | --- | --- |
| Checklist proposals, approval and rejection | Owners propose steps; the leader approves them before they take effect, or returns the proposal with a reason. | [Read](USER-GUIDE.md#keep-execution-discussion-and-feedback-clear) |
| Save checklist completion | Compare saved progress with unsaved checks, save with Save checked progress, or undo unsaved changes. A 100% checklist still needs result submission and review. | [Read](USER-GUIDE.md#keep-execution-discussion-and-feedback-clear) |
| Progress and comments | Progress records the current result, next step and next feedback time. Comments support discussion and do not extend formal feedback. | [Read](USER-GUIDE.md#keep-execution-discussion-and-feedback-clear) |
| Blockers and help | Describe the obstacle and requested help, name a helper, receive a reply and resolve the blocker as owner. | [Read](USER-GUIDE.md#keep-execution-discussion-and-feedback-clear) |
| Request requirement changes | Non-leader participants can request changes. The leader may adjust the agreement or respond and close the request without changing it. | [Read](USER-GUIDE.md#change-requirements-and-confirm-the-new-version) |
| Confirm agreement versions | Owners read the differences and confirm the current version before submitting a result. | [Read](USER-GUIDE.md#change-requirements-and-confirm-the-new-version) |
| Checklist changes affecting scope or criteria | Approval requires a confirmation deadline and creates a new agreement version for the owner to confirm. | [Read](USER-GUIDE.md#change-requirements-and-confirm-the-new-version) |
| Pending results after an adjustment | Adjusting an agreement during review retains the old result as Superseded and returns the task to In progress. | [Read](USER-GUIDE.md#change-requirements-and-confirm-the-new-version) |

## Task relations

| Feature | How to use it | Read |
| --- | --- | --- |
| Parent tasks and parent review | Each task has at most one parent. A parent needs its own result submission and review after its children complete. | [Read](USER-GUIDE.md#set-task-relations-and-use-the-graph) |
| Prerequisites | A prerequisite must be Completed before the dependent result can pass review. Work may start earlier. | [Read](USER-GUIDE.md#set-task-relations-and-use-the-graph) |
| Related tasks and removing relations | Related links record background. Removing a relation does not delete tasks. Parent and dependency cycles are prohibited; see the guide for permissions and constraints. | [Read](USER-GUIDE.md#set-task-relations-and-use-the-graph) |

## Search, filters and pending actions

| Feature | How to use it | Read |
| --- | --- | --- |
| Tree, Gantt, graph, details and URLs | Select a task to read its details. Use Markdown sections and Edit/Preview for agreements, and copy a task URL to reopen or share it. | [Read](USER-GUIDE.md#read-a-task-before-acting) |
| Gantt delivery schedule | Read planned ranges, deadline markers and lifecycle indicators. Switch timeline scales, locate today or the selection, and display prerequisite arrows. | [Read](USER-GUIDE.md#read-the-delivery-schedule) |
| Member relationship filters | Select a member and combine owner, creator/issuer and approval/review relationships. Choices persist per account in this browser. | [Read](USER-GUIDE.md#filter-tasks-by-member) |
| Graph controls | Focus on direct relations, zoom, fit, locate or reset the view. Drag nodes or the canvas to arrange the view. | [Read](USER-GUIDE.md#set-task-relations-and-use-the-graph) |
| Search, project and status filters | Search by title or number digits and select a project and stage. Parents can explain hierarchy without increasing the match count. | [Read](USER-GUIDE.md#search-and-filter-by-project-status-and-time) |
| Time filters and personal settings | Filter by week, month or custom dates; save separate project settings and choose whether to include undated or earlier unfinished tasks. | [Read](USER-GUIDE.md#search-and-filter-by-project-status-and-time) |
| Pending actions and overdue reminders | Find approval, acceptance, confirmation, help, progress or review assigned to you. Leaders can follow the whole team. | [Read](USER-GUIDE.md#check-the-action-inbox-and-operation-history) |
| Task-stage feedback | Read workflow receipts, resulting stages and next handlers; inspect task activity for recorded teammate changes. | [Read](USER-GUIDE.md#check-the-action-inbox-and-operation-history) |
| Task activity and team updates | Read who acted, when and which fields changed. Filter team updates by author and load older records. | [Read](USER-GUIDE.md#check-the-action-inbox-and-operation-history) |
| Panels and mobile views | Remember panel sizes and visibility, focus on details and restore the previous layout. Use tree, workspace and details tabs on a phone. | [Read](USER-GUIDE.md#search-and-filter-by-project-status-and-time) |

## Projects and accounts

| Feature | How to use it | Read |
| --- | --- | --- |
| Project people and color | Leaders and project managers can maintain members and color; only the leader can transfer project management. | [Read](USER-GUIDE.md#maintain-the-project-and-accounts) |
| Sign in, switch users and sign out | Switch demo accounts to try different responsibilities. Drafts are visible only to their creator. | [Read](USER-GUIDE.md#maintain-the-project-and-accounts) |
| Create accounts and choose roles | Administrators create accounts and select roles. Account roles differ from task-specific owner and reviewer assignments. | [Read](USER-GUIDE.md#maintain-the-project-and-accounts) |
| Disable and enable accounts | Transfer outstanding responsibilities before disabling. Leaders and your own account cannot be disabled this way; active-status changes revoke existing sessions. | [Read](USER-GUIDE.md#maintain-the-project-and-accounts) |
| Language and theme | English/Chinese and light/dark choices stay in the browser. Task text is not automatically translated. | [Read](USER-GUIDE.md#change-language-theme-and-mobile-view) |
